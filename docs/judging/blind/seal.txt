FLIPSIDE · COMPONENT SPEC · M1


flip seal v1
Before the pull request is reviewed, the author's machine fixes every message of
the agent session into one 32-byte fingerprint and writes it into git. Later, any
single quote from that session can be shown to the reviewer with a short proof that
it was there all along, while the rest of the session stays on the author's machine.

REVIEWER SIDE


flip verify checks, in order
     flip verify --commit a41b2c7 --manifest manifest.json disclosure.json
  1         NO_SEAL                               The named commit has no Flipside-Seal: trailer, or more than
                                                  one.


  2         WRONG_COMMIT                          The disclosure names a different commit from the question. A re-
                                                  seal in a later commit cannot answer an earlier question.


  3         NOT_IN_PR                             The commit is not an ancestor of, or equal to, the PR head (git
                                                  merge-base --is-ancestor).

  4         MANIFEST_HASH                         SHA-256 of the manifest does not match the trailer.


  5         MANIFEST_MISMATCH                     The leaf's metadata differs from manifest entry i.


  6         BAD_SIZE                              i   ≥ n, or the proof length is wrong for that index and size.
  7         PROOF_FAIL                            Hashing up from the leaf (RFC 9162 §2.1.3.2) does not reach the
                                                  root. A forged or edited chunk stops here.


  ✓         OK                                    leaf 3 (step 3, chunk 0) against seal 50ab222 in commit
                                                  a41b2c7


The reviewer-agent then computes coverage itself from the public manifest, so it does not
have to trust the author's count: 1 sealed step touched auth/session.py: 1
disclosed, 0 withheld. On the author's side, flip prove refuses with
SESSION_CHANGED if the session file's SHA-256 differs from the one recorded at seal time.

Decisions
 ID     CHOSEN                                            REJECTED, AND WHY

 D1     One step per message; assistant blocks merge      One step per content block: splits the reasoning from the edit it explains and
        by message.id                                     breaks the file check

 D2     Thinking blocks not sealed                        Sealing them: often redacted or signed, and the most private part of the
                                                          session

 D3     Chunks of at most 300 characters, cut at          Fixed windows cut words mid-quote; sentence splitting depends on language
        whitespace

 D4     Metadata (step, tools, files) inside each leaf    Text-only leaves: the reviewer could not verify that the step touched the file

 D5     Salts derived from one local key by HMAC          A stored random salt per leaf means thousands of secrets; no salt makes
                                                          short chunks guessable

 D6     RFC 9162 Merkle tree with SHA-256                 Duplicate-last-leaf trees: known mutation bug (CVE-2012-2459)

 D7     Empty seal commit with a trailer; --amend         git notes are not pushed by default and GitHub hides them; amending by
        opt-in                                            default rewrites pushed history

 D8     Public manifest posted in the room, its hash in   Committing it adds a file to the PR the owning team merges
        the trailer

 D9     Verify against the commit the question names      Verifying against HEAD lets a re-seal win

GATES


M1 is done when
  G1             Inclusion proofs verify for every leaf of every tree size from 1 to 256. Prototype passes 1 to 69.



  G2             Flipping any single bit of the text, salt, a sibling hash, the index, n or the root makes verify fail with the
                 right code.



  G3             The example on this page reproduces root 50ab222b… and manifest 6311c5cd… byte for byte.
                 Prototype passes.



  G4             Sealing a real Claude Code session twice with the same key gives the same root.
  G5        End to end in git: an edited quote gives PROOF_FAIL ; a re-seal after the question gives
             WRONG_COMMIT ; an edited session gives SESSION_CHANGED .



  G6        ruff and mypy clean; make test green on two consecutive runs.
