Shortlist: Yes, but only on a condition. It is one of the few entries where removing Switch removes the safety property, and it should drop off if make replay fails from a clean clone.

Costliest weaknesses
1. Most of it is not built. Fix: build the narrow path first: seal, verify, JSON filter, approval, replay. Make make replay reproduce the four refusals from a clean clone in CI, and run K3 before recording. Cut the fixture study before any of these.
2. "Verified" proves that a quote exists in the session, not that it answers the question or that nothing was left out. The author's agent picks the chunk, and the author can hold back the damaging one. Fix: post a coverage line with each answer that plain Python computes, for example "4 sealed steps touched auth/session.py: 1 disclosed, 3 withheld", with leaf indices.
3. The security panel will probe three gaps.
   - The 300-character leaves are unsalted, so sibling hashes in a proof let the reviewer confirm guesses about short chunks.
   - The plan states no domain separation between leaf hashes and node hashes.
   - file and lines are free strings, so a prompt injection can still reach the author's session.
   Fix: salt each leaf, use the RFC 6962 leaf and node prefixes, accept file only if it is in the PR's changed-file list, and check lines against a strict regex.

Doubted claims
- "Priya learns about the TTL change at the same moment as the reviewer." This is false: she sees the chunk on the approval card first and can decline it.
- "Changing the session after the questions arrive breaks the seal." The author can push a new commit with a new seal from an edited session, and verify then checks the new head. A force-push showing in the timeline is not a check. Fix: pin the seal to the commit the questions refer to, and make flip verify reject a later root.
- The example quote contains "…". Text with parts cut out cannot hash to the leaf, so the text shown and the bytes verified are different.
- The fixture study needs 30 PRs, 2 outside reviewers and a teammate who has not seen the tool, which is unlikely in hackathon time. The hidden changes are also visible in the diff, so the study measures how carefully reviewers read more than it measures Flipside.
