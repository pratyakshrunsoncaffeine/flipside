Flipside · component spec · M1

flip seal v1

Before the pull request is reviewed, the author's machine fixes every message of the agent session into one 32-byte fingerprint and writes it into git. Later, any single quote from that session can be shown to the reviewer with a short proof that it was there all along, while the rest of the session stays on the author's machine.

Awaiting approval Math prototyped: proofs verify for every tree size 1 to 69 Python stdlib only Claude Code sessions

What a verified quote proves

  • These exact bytes were in the session when it was sealed.
  • They belong to step s, chunk c, with the tools and files the manifest lists.
  • The seal was in the commit the question named, so editing the session afterwards cannot change the answer.
  • How many other sealed steps touched the same file and stayed hidden.

What it does not prove

  • That the session file is genuine. An author who forges a session before sealing is out of scope.
  • That the quote fully answers the question. The coverage line shows what was withheld.
  • That this session wrote the code. Work done outside the agent has no session evidence.
Pipeline

From session file to seal

  1. ReadLoad the Claude Code session JSONL. Keep main-thread user and assistant lines only.
  2. StepsOne step per message. Assistant lines that share message.id merge; each tool result is its own step.
  3. ChunksNFC, CRLF to LF, then at most 300 characters per chunk, cut at the last space or newline.
  4. LeavesEach chunk plus its metadata, as canonical JSON, salted and hashed with prefix 0x00.
  5. TreeRFC 9162 Merkle tree over all leaves, inner nodes hashed with prefix 0x01.
  6. CommitAn empty seal commit carries the root, leaf count and manifest hash as a Flipside-Seal: trailer.
  7. RoomWhen #pr-142 opens, author-agent posts the seal line and manifest. Switch timestamps it.

Rules

Exact construction

Steps and files

A step's text is its text blocks verbatim, then each tool call as [tool Edit] plus the canonical JSON of its input. A tool result's text is its text content; an image becomes [image sha256:…].

files comes only from structured tool input: file_path, notebook_path, path. Paths are repo-relative POSIX; anything outside the repo becomes <external>. A tool result inherits the files of its call through tool_use_id. Bash commands are sealed as text but tag no files.

Thinking blocks are not sealed.

Hashes

# K: 32 random bytes, .git/flipside/<root>.key, mode 0600, never sent
leaf  = canonical_json({v, session, step, chunk,
                        role, tools, files, text})
salt  = HMAC-SHA256(K, "flipside/salt/v1" ||
                       canonical_json([session, step, chunk]))
L(i)  = SHA-256(0x00 || salt || leaf)
N     = SHA-256(0x01 || left || right)
split = largest power of two < n      # RFC 9162 §2.1.1
root  = MTH(L(0) … L(n-1))
manifest = canonical_json([leaf minus text, plus i, for each leaf])

Canonical JSON: sorted keys, no spaces, UTF-8, integers and strings only, so every implementation produces the same bytes.

Reviewer side

flip verify checks, in order

flip verify --commit a41b2c7 --manifest manifest.json disclosure.json
1NO_SEALThe named commit has no Flipside-Seal: trailer, or more than one.
2WRONG_COMMITThe disclosure names a different commit from the question. A re-seal in a later commit cannot answer an earlier question.
3NOT_IN_PRThe commit is not an ancestor of, or equal to, the PR head (git merge-base --is-ancestor).
4MANIFEST_HASHSHA-256 of the manifest does not match the trailer.
5MANIFEST_MISMATCHThe leaf's metadata differs from manifest entry i.
6BAD_SIZEi ≥ n, or the proof length is wrong for that index and size.
7PROOF_FAILHashing up from the leaf (RFC 9162 §2.1.3.2) does not reach the root. A forged or edited chunk stops here.
✓OKleaf 3 (step 3, chunk 0) against seal 50ab222 in commit a41b2c7

The reviewer-agent then computes coverage itself from the public manifest, so it does not have to trust the author's count: 1 sealed step touched auth/session.py: 1 disclosed, 0 withheld. On the author's side, flip prove refuses with SESSION_CHANGED if the session file's SHA-256 differs from the one recorded at seal time.

The manifest is public, so it reveals the step count, roles, tool names, repo-relative paths and chunk counts (length to the nearest 300 characters). It never contains text.

Gates

M1 is done when

  • G1Inclusion proofs verify for every leaf of every tree size from 1 to 256. Prototype passes 1 to 69.
  • G2Flipping any single bit of the text, salt, a sibling hash, the index, n or the root makes verify fail with the right code.
  • G3The example on this page reproduces root 50ab222b… and manifest 6311c5cd… byte for byte. Prototype passes.
  • G4Sealing a real Claude Code session twice with the same key gives the same root.
  • G5End to end in git: an edited quote gives PROOF_FAIL; a re-seal after the question gives WRONG_COMMIT; an edited session gives SESSION_CHANGED.
  • G6ruff and mypy clean; make test green on two consecutive runs.

Approving this also changes the pitch

  1. The coverage line counts steps, not leaves, and the reviewer-agent computes it from the manifest instead of the author-agent.
  2. The trailer goes on a dedicated seal commit, not on whatever the PR head commit is.
  3. The seal line is also posted in #pr-142 when the room opens, which answers the Codex judge's "no independent record" point.
  4. The pitch example's seal id becomes 50ab222, to match this page.
